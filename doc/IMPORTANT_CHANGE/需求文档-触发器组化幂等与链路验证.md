# 需求文档：触发器组化幂等、this.auth 身份注入与链路验证能力

> 2026-09-17。背景：请假审批会话暴露三类系统性问题——触发器正确性建立在未验证的顺序/幂等假设上、
> 无会话上下文 `this.auth` 静默渲染 NULL、全链路零端到端验证（断链/审批人缺失要到真实运行才静默暴露）。
> 本文档描述平台底座与 Agent 能力的对应改造。变更分四组：底座（A）、校验器（B）、
> 验证能力（C）、Agent 工具（D）。

## A. 底座

### A1 触发器组化（同节点同事件按序派发）
- 同一来源节点在同一事件上的多条触发器编为一组：`workflow_trigger_outbox` 新增 `group_id`（uuid）+
  `group_order`（0 起按配置顺序）。ddl-auto=update 自动建列。
- `TriggerDispatcher` 派发门槛：组内前序成员未 `DISPATCHED` 时后续成员不派发——
  失败退避重试也不会乱序（"先回写状态 155、再扣减余额 157"这类顺序依赖成为被引擎保证的契约）。
- 前序成员进入 DEAD 时后续成员永不执行（宁可不扣，不可错账）；组行为可用 `rehearse_triggers` 预演。

### A2 幂等去重真正落地
- outbox 幂等键从随机 UUID 改为确定键 `"otb-"+行id`（先落库拿 id 再回写键）。
- `InvocationService` 根调用（depth=0）按 `idempotency_key + status=SUCCESS` 查重：
  at-least-once 重发（目标已成功但响应丢失）直接去重返回，不再重复执行（防重复扣减）。
  `ExecutionContext.child()` 不再下传幂等键——子调用重跑是整组重试语义的一部分。

### A3 this.auth 身份注入
- 硬失败：执行上下文没有任何用户身份、且模板引用 `{{ this.auth.* }}` 时直接报错，
  不再静默渲染 NULL（"WHERE user_id = NULL 命中 0 行还被当成成功"是最危险的静默断链）。
- 正确注入：触发器/编排路径（principal = on-behalf-of 发起人）经 `QueryService.runAsUser` 以
  发起人身份解析 this.auth——回写类查询从此可以安全使用 `{{ this.auth.userId }}` 做数据归属。

### A5 预览身份切换（preview-as）
- `POST /queries/{id}/run?previewAsUserId=N`：设计者以指定平台用户身份执行查询（仅应用所有者，
  service 内校验）。预览面板内置"身份预览"切换器：页面身份（`__LUBAN_USER__`）与查询 this.auth
  同步切换。验收判据：不同账号预览"我的XX"查询，结果集必须不同。

## B. 校验器（把页面校验的成功模式复制到查询与链路）

### B2 lint_workflow 增强
- 新端点 `POST /lint/workflow-definition/{processId}`：服务端自动装载绑定表单字段
  （`lint_workflow` 工具优先走它）。
- 新增检查：触发器事件合法性、target.type/ref 完整性、**paramsMapping 的 form.data.* 字段必须存在于
  绑定表单**（断链 ERROR）、条件表达式必须引用表单字段（WARNING）、同节点同事件多触发器
  顺序提示（组内按配置顺序派发，存在先后依赖可用预演验证）。

### B3 startWorkflow 断链校验（页面校验器）
- `codeValidate` 新增 `validateStartWorkflowContract`：formData 缺失/空对象 → 阻断；
  字面量缺业务 id、变量传入无法静态核对 → 警告并回显字段清单，要求与绑定表单契约逐字一致。

### B1 查询静态 lint
- 新模块 `queryLint.ts`：身份域检查（"我的XX/当前用户"类查询必须用 `{{ this.auth.* }}` 过滤，
  `this.params` 传身份 → 阻断）；回写守卫检查（UPDATE/DELETE 无 status 条件 → 警告）。
- `create_query`/`update_query` 自动执行（errors 级阻断）；另有独立 `lint_query` 工具
  （DBA 与主智能体可用）复核存量/草稿 SQL。

## C. 验证能力（"完成"= 链路验证通过，不是资源创建成功）

### C1 触发器预演 rehearse_triggers
- 端点 `POST /workflows/{id}/rehearse-triggers`（body: `sampleFormData` + `sampleInitiatorId`）。
  不发起实例、不执行写操作：推演分支路径（ConditionEvaluator）、审批人解析（空 → ERROR：
  真实运行该节点会被静默跳过）、paramsMapping 解析结果与 NULL 参数、QUERY 目标渲染后 SQL、
  必填参数缺失。Agent 工具 `rehearse_triggers` 已注册（流程助手 + 主智能体）。
- 发布前/页面挂接后必须预演主分支与驳回分支各一遍。

### C2 计划强制链路验证步骤
- `derivePlanFromAnalysis` 在每条流程的"发起链路接入"后自动追加 `rehearse_triggers` 收尾步骤
  （依赖发布 + 挂接）。
- `stepVerifier` 对该步骤做证据核验：result 无预演摘要 → 拒绝 completed；预演报出
  "审批人解析为空/断链/必填参数缺失" → 拒绝 completed，必须修复重演。

## A4 审批人解析策略（第二批）
- 节点 data.config 可选声明 `resolutionPolicy: skip | fail | suspend`（默认 skip，历史行为：留痕后跳过继续推进）。
  fail = 当前操作报错回滚、操作方立即看到错误；suspend = 实例置 SUSPENDED 等待管理员处理（历史留痕 SUSPENDED）。
  审批结果依赖回写触发器的流程建议 fail/suspend——默认 skip 的"审批被静默跳过、APPROVED 触发器永不执行、实例正常完结"是静默断链。
- lint 增加组织架构前置数据检查（定义级 lint）：流程使用 leader 节点但 user_dept 无任何主部门配置 leader_id → ERROR；
  使用 department_head 节点但 departments 无任何 manager_id → ERROR。另加建议用 rehearse_triggers 预演的 WARNING。

## A5 触发器 minAffectedRows（第二批）
- 触发器顶层可选声明 `minAffectedRows`（仅 QUERY 目标）：实际影响行数低于该值按失败重试/死信处理，
  "必命中"回写命中 0 行不再被当成派发成功。守卫型查询（预期可能 0 行）禁止声明。outbox 新列 min_affected_rows。

## A6 触发器链路可观测（第二批）
- 新控制器 `/api/v1/workflow-observability`：`GET /instances/{id}/trigger-outbox`（实例派发记录：
  组/顺序/状态/重试/最后错误，实例查看权限复用 getInstance）与 `GET /trigger-outbox/dead`（最近死信，需 APPS_READ）。
- Agent 工具：`get_instance_timeline`（实例时间线，重点标注 SKIP/SUSPENDED/FAIL 留痕）与
  `list_trigger_outbox`（派发记录/死信查询），主智能体与流程助手可用。

## C4 计划漂移检测（第二批）
- delegate_query / delegate_workflow 完成时，把结构化 outcomes 与当前活跃计划的步骤声明比对：
  产出资源未出现在任何步骤声明中 → 在委派结果中附加"计划漂移提醒"，要求主智能体用 adjust_plan 回写
  （2026-09-17 请假案例中 UpdateLeavePending 计划外创建未回写，即此问题）。纯提醒，不阻断。

## D 组（第二批）
- **D2 汇报纪律**：DBA 与流程助手提示词新增三段式最终汇报要求——【结论】【证据】【风险与残留】，
  结论不得与证据矛盾、风险禁止写成"可放心上线"。
- **D3 测试回滚**：`execute_sql` 新增 rollback 参数——语句在事务中执行后回滚（结果带 rolledBack=true），
  测试写 SQL 效果不再污染演示数据（此前请假案例测试实扣李娜余额并打回状态，即此问题）。
- **D4 遗留资源扫描**：`list_stale_resources` 工具（主智能体）——未被页面绑定的查询、未绑定表单的
  DRAFT 流程、未绑定的表单；创建新计划前先扫描，存量资源要么复用（先 lint_query 验证规范）要么显式清理。
- **预览身份切换组件化**：InteliPreview 身份预览下拉使用平台统一 Select 组件（@/components/Select）。

## D. Agent 侧约定
- `rehearse_triggers` 的 `sampleFormData` 字段必须与绑定表单逐字一致、含业务记录 id（写查询返回的
  insertId）；`sampleInitiatorId` 必须用真实平台用户（`search_platform_users`），审批人解析依赖
  `user_dept.leader_id` / `departments.manager_id`。
- 触发器组顺序是配置契约：APPROVED 回写存在先后依赖时按数组顺序声明（回写状态在前、扣减在后），
  或合并为单条原子 SQL / 编排目标（幂等由状态守卫 + 数据库唯一约束保证）。
