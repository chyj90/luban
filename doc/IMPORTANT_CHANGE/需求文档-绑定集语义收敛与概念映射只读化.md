# 需求文档：绑定集语义收敛与概念映射只读化

> 2026-09-19。背景：多实例/多数据源改造后，平台确立了"**一个数据源一套绑定集**"的模型，但概念编辑器
> 仍保留映射/JOIN 映射的手工增删改表单，且列表不标数据源归属，造成"概念编辑器在管全局物理映射"的
> 认知混乱。本需求把概念编辑器收敛为**只读落地视图**，物理映射的维护完全交给自动匹配（本体自学习），
> 并顺手修复 SQL 生成端不按数据源收敛的隐患。变更随本次提交落地。

## 一、必须长期记住的模型设定（防止遗忘）

1. **一个数据源一套绑定集**：`binding_profile` 对 `datasource_id` 唯一。绑定集承载的是**数据源专属的
   语义词典资产**——术语词典（方言同义词→概念）、枚举字典（列枚举值缓存，供 value_origins 免实连校验）
   + 映射覆盖状态（ACTIVE/EMPTY）。**绑定集不是映射的存储体。**
2. **映射资产永远存在 `concept_mapping` / `concept_join_mapping`**，按 `(concept_id, datasource_id)`
   归属（唯一约束即四元组 concept+table+column+datasource）。同一集团概念在 N 个数据源落地 = N 行，
   这是本质的多对多，不要试图把映射搬进绑定集 JSON——会丢掉反向按概念检索（本体图/ContextBuilder/
   快照/变更审核都在用）、@Version 乐观锁、confidence、is_auto 溯源与唯一约束。
3. **概念与数据源无关**（集团级口径）；带数据源上下文的写路径只有两条：自动匹配（自学习主链路）与
   绑定管理的词典引导。数据源删除时级联清理概念映射与绑定集（8e37221 已落）。
4. **SQL 生成/执行必须先收敛到单一数据源**：`SqlExecutionService` 按 scope 过滤映射（原有）；
   `SqlGeneratorService` 现在也强制收敛（本次新增，见 §三）。

## 二、已落地改造：概念编辑器映射只读化

本体是自学习、自进化的组成部分，**没有人会手工逐行调映射**；人工干预的正确姿势是调整绑定管理的
术语词典/枚举字典后重新自动匹配，而不是直接改物理映射行。

| # | 改造点 | 文件 | 说明 |
|---|--------|------|------|
| 1 | 字段映射/JOIN 映射卡片改只读 | `ConceptEditorPage.tsx` | 删除 ✎/× 操作与「+ 添加映射 / + 添加 JOIN」按钮、两个表单弹窗及其全部处理器；卡片列表按数据源分组排序 |
| 2 | 行级数据源归属标注 | `ConceptEditorPage.tsx` | 每行前置数据源名 tag（`datasourceNameMap`，删除态数据源回退 `数据源#id`），消除"多数据源映射混排分不清"的问题 |
| 3 | 新增「映射维护」说明卡 | `ConceptEditorPage.tsx` | 说明"映射由自动匹配自学习维护、概念编辑器只读"，提供跳转 `/modeling/binding-profiles`（绑定管理）入口 |
| 4 | 清理无用 import | `ConceptEditorPage.tsx` | 移除 create/update/deleteConceptMapping、create/update/deleteConceptJoinMapping |

**注意**：后端 `ConceptMappingController` / `ConceptJoinMappingController` 的 REST CRUD 端点**保留未动**——
自动匹配管道与 Agent 工具仍走 service 层同一条写路径；本次只收掉前端的手工编辑入口，不改 API 契约。

## 三、已落地改造：SQL 生成端数据源收敛（修多库混编隐患）

- `SqlGeneratorService.generateSql(conceptIds, filters)` → `generateSql(conceptIds, filters, datasourceId)`：
  - 传入 datasourceId 时按 `findByConceptIdInAndDatasourceIdIn` 收敛映射；为空时若概念映射落在
    **多个数据源**，直接 `IllegalStateException` 报错并列出候选数据源（口径与 `SqlExecutionService
    .resolveDatasourceId` 一致：宁报错不混编）。
  - JOIN 查找从「按表名全库捞 `findByConceptIdInAndJoinTable`」改为「先按 scope 数据源取 JOIN 再内存过滤」，
    杜绝把别的库的同名 JOIN 条件拼进来。
  - 单数据源行为完全不变（此前 `findByConceptId` 循环拼接的语义在单库场景下等价）。
- `Nl2SqlController.generate` 透传可选 `body.datasourceId`。
- 前端 `generateNl2Sql` 增加 `datasourceId?`；`QueryEditor` 按当前查询的 `query.datasourceId` 传入；
  Agent 工具 `concept:nl2sql` 增加 `datasourceId` 可选参数并在描述中声明"跨数据源必填"。
