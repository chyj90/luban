## 一、背景

当前流程引擎（ProcessEngine）功能完整，支持审批、驳回、转办、加签、委派、冻结、终止等全部操作。但**所有接口均无权限校验**，任何认证用户调用 API 都能操作任意流程任务，存在严重安全漏洞。

### 影响范围

| 风险等级 | 问题 | 影响 |
|:--:|------|------|
| 🔴 严重 | 非审批人可审批/驳回任意任务 | 流程审批形同虚设，任何用户可操作他人任务 |
| 🔴 严重 | 任务转办/加签/委派无归属校验 | 可篡改任意任务的审批人列表 |
| 🟠 高 | 流程取消/冻结/终止无权限限制 | 可恶意终止他人流程 |
| 🟡 中 | 驳回后重新提交无发起人校验 | 数据一致性问题 |

---

## 二、需求范围

### 2.1 本次需求（Phase 1：审批人校验）

**目标**：对任务操作接口增加归属校验，确保只有任务审批人才能操作。

**涉及接口**（共 6 个）：

| 接口 | 路径 | 当前问题 | 校验规则 |
|------|------|------|------|
| 审批通过 | `PUT /api/v1/tasks/{id}/approve` | 无校验 | operatorId ∈ allAssigneeIds |
| 审批驳回 | `PUT /api/v1/tasks/{id}/reject` | 无校验 | operatorId ∈ allAssigneeIds |
| 转办 | `PUT /api/v1/tasks/{id}/transfer` | 无校验 | operatorId = assigneeId 或 ∈ allAssigneeIds |
| 加签 | `PUT /api/v1/tasks/{id}/add-sign` | 无校验 | operatorId ∈ allAssigneeIds |
| 委派 | `PUT /api/v1/tasks/{id}/delegate` | 无校验 | operatorId ∈ allAssigneeIds |
| 逐级驳回 | `POST /api/v1/tasks/{id}/reject-previous` | 无校验 | operatorId ∈ allAssigneeIds |

### 2.2 后续需求（Phase 2/3，不在本次范围）

- 流程定义权限（create/update/publish/delete）
- 流程启动权限
- 流程运维权限（cancel/freeze/unfreeze/forceStop）
- 驳回后重新提交权限

## 三、详细设计

### 3.1 核心校验逻辑

在 `ProcessEngine` 中新增统一的审批人校验方法：

```java
/**
 * 校验操作人是否有权处理该任务
 * @throws RuntimeException 如果操作人不在审批人列表中
 */
private void checkTaskAssignee(WorkflowTask task, Long operatorId, String operation) {
    Set<Long> allAssignees = parseIdSet(task.getAllAssigneeIds());
    
    // 如果 allAssigneeIds 为空（兼容历史数据），只校验 assigneeId
    if (allAssignees.isEmpty()) {
        if (task.getAssigneeId() != null && task.getAssigneeId().equals(operatorId)) {
            return;
        }
        throw new RuntimeException("您不是该任务的审批人，无权进行" + operation + "操作");
    }
    
    if (allAssignees.contains(operatorId)) {
        return;
    }
    
    throw new RuntimeException("您不是该任务的审批人，无权进行" + operation + "操作");
}
```

### 3.2 各接口改造点

#### 3.2.1 completeTask（审批通过/驳回）

**代码位置**：`ProcessEngine.java:L125`

**当前代码**：
```java
public WorkflowTask completeTask(Long taskId, String action, String comment,
                                  Long operatorId, String operatorName) {
    WorkflowTask task = workflowTaskRepository.findById(taskId)...;
    // 直接处理，无校验
```

**改造后**：
```java
public WorkflowTask completeTask(Long taskId, String action, String comment,
                                  Long operatorId, String operatorName) {
    WorkflowTask task = workflowTaskRepository.findById(taskId)...;
    
    // 新增：审批人校验
    checkTaskAssignee(task, operatorId, "审批");
    
    // 原有逻辑不变...
```

**特殊说明**：
- 一票否决模式（all_pass + REJECT）下，任一审批人都有权驳回，无需额外处理
- 比例通过模式（ratio_pass）下，任一审批人都有权审批/驳回
- 依次审批模式（sequential）下，`allAssigneeIds` 已包含所有审批人，当前处理人由 `allAssigneeIds.indexOf(operatorId)` 确定

### 3.3 错误响应格式

所有校验失败返回 403 Forbidden：

```json
{
  "error": "FORBIDDEN",
  "message": "您不是该任务的审批人，无权进行审批操作",
  "timestamp": "2026-08-24T10:30:00"
}
```

### 3.4 不纳入本次校验的操作

以下操作属于**实例级操作**（非任务级），不在 Phase 1 范围：

| 操作 | 原因 |
|------|------|
| `rejectToNode`（驳回至指定节点） | 实例级操作，Phase 2 处理 |
| `forceJump`（强制跳转） | 管理员操作，Phase 2 处理 |
| `cancelProcess`（撤回） | 需校验发起人，Phase 2 处理 |
| `freeze/unfreeze`（冻结/解冻） | 管理员操作，Phase 2 处理 |
| `forceStop/forceWithdraw`（强制终止/撤回） | 管理员操作，Phase 2 处理 |
| `resubmitInstance`（驳回后重新提交） | 需校验发起人，Phase 2 处理 |

## 四、影响分析

### 4.1 前端影响

**无新增页面，无 UI 调整**。Phase 1 是纯后端改动，前端已有页面无需修改。

原因：前端「我的工作 → 待处理」Tab 已通过 `getPendingTasks(user.getId())` 只展示当前用户的任务，用户只能看到自己有权限的任务。后端校验是**防御性**的，防止绕过前端直接调用 API。

**建议优化**（可选，不阻塞上线）：

当前 axios 拦截器（`client.ts:L34-L42`）对所有错误统一处理，403 无特殊提示。建议增加 403 分支：

```typescript
// client.ts 拦截器中增加
if (error.response?.status === 403) {
  const backendMsg = error.response?.data?.message || '您没有权限执行此操作';
  // 触发 toast 提示，由各页面 catch 块统一处理
}
```

已有错误处理无需改动——各页面 `catch` 块已调用 `toast('操作失败', 'error')`，403 返回的 `message` 会自动透传。

### 4.2 历史数据兼容

- `allAssigneeIds` 可能为空（历史数据）→ 降级为仅校验 `assigneeId`
- `allAssigneeIds` 为 JSON 数组 `[1, 2, 3]` → 正常解析校验

### 4.3 测试任务兼容

测试流程（`isTest=true`）同样需要校验，与正式流程一致。

#### B.5 安全验证（403 场景）

**验证目标**：test_outsider（非审批人）尝试直接调用 API 审批 test_starter 发起的任务，预期返回 403。

**步骤**：

| 步骤 | 窗口 | 操作人 | 操作 |
|:--:|:--:|:--:|------|
| 1 | 窗口 1 | test_starter | 再次发起「权限校验测试-真实」，审批人为 test_approver |
| 2 | 窗口 2 | test_approver | 打开 DevTools（F12）→ Network → 刷新「我的工作」→ 找到 `/api/v1/tasks?status=PENDING` 请求 → 从 Response 复制任务 `id`，记为 `{TASK_ID}` |
| 3 | 窗口 3 | test_outsider | DevTools → Console，执行以下 6 条命令，预期全部返回 403 |

```javascript
// 1. 审批
fetch('/api/v1/tasks/{TASK_ID}/approve', {method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({comment:'test'})}).then(r=>r.json())
// 预期: { error: "FORBIDDEN", message: "您不是该任务的审批人，无权进行审批操作" }

// 2. 驳回
fetch('/api/v1/tasks/{TASK_ID}/reject', {method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({comment:'test'})}).then(r=>r.json())

// 3. 转办
fetch('/api/v1/tasks/{TASK_ID}/transfer', {method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({targetUserId:1,targetUserName:'test',comment:'test'})}).then(r=>r.json())

// 4. 加签
fetch('/api/v1/tasks/{TASK_ID}/add-sign', {method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({addUserId:1,addSignType:'AFTER',comment:'test'})}).then(r=>r.json())

// 5. 委派
fetch('/api/v1/tasks/{TASK_ID}/delegate', {method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({delegateUserId:1,comment:'test'})}).then(r=>r.json())

// 6. 逐级驳回
fetch('/api/v1/tasks/{TASK_ID}/reject-previous', {method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({comment:'test'})}).then(r=>r.json())
```
