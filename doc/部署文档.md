# 鲁班平台 部署文档

> 适用版本：运营商行业语义包开箱即用版。阅读对象：实施工程师、平台管理员。

## 1. 系统组成

| 组件 | 技术栈 | 默认端口 | 说明 |
|---|---|---|---|
| 后端 | Spring Boot 3 / JPA | 8080 | 平台服务，含问数 agent、语义底座 |
| 前端 | React / Vite | 5173 (dev) | 平台界面，生产构建为静态资源 |
| 语义服务 | Python (FastAPI) | 8765 | 概念向量嵌入 + FAISS 检索 + 代码沙箱 |
| 数据库 | MySQL 8.x | 3306 | 平台系统库 `luban`（仅存平台元数据） |

数据边界（重要）：平台系统库只存平台元数据（账号、角色、概念、映射等）。业务数据（包括演示数据）一律放在外部业务库——运营商语义包的演示表建在独立库 `luban_demo_operator`，与平台库物理解耦，删除演示库不影响平台。

## 2. 环境要求

- JDK 17+、Maven 3.8+
- Node.js 18+
- MySQL 8.x（部署账号需对平台库有读写权限；**启用行业语义包需要建库权限**）
- Python 3.10+（语义服务；启用代码沙箱需本机 Docker）

## 3. 快速开始（演示 / POC，约 15 分钟）

```bash
# 1. 配置数据库连接（backend/src/main/resources/application.yml）
#    spring.datasource.url 默认 jdbc:mysql://localhost:3306/luban?...createDatabaseIfNotExist=true
#    库不存在会自动创建，无需手工建库

# 2. 启动语义服务（首次会构建沙箱镜像，需要 Docker）
cd embedding-service
pip install -r requirements.txt
./start.sh -d          # 日志: logs/server.log，端口 8765

# 3. 启动后端（自动生成并持久化密钥，详见第 5 节）
cd backend
./start.sh -d          # 日志: logs/backend.log，端口 8080
# 启动日志出现「运营商语义包就绪」即行业包生效

# 4. 启动前端（开发模式）
cd frontend
npm install
npm run dev            # http://localhost:5173
```

首次启动自动初始化：角色/权限/审批流种子、超管账号 **root / 123456**（登录后请立即修改）、平台语义包（组织/人员/部门）、运营商语义包（见第 4 节）。

**开箱验证**：登录 → 智能问数 → 点模板卡「问指标」或直接问"上月出账收入是多少？"→ 得到带口径来源的回答 → 建模中心 → 语义包回归 → 运营商语义包 → 运行，8 个用例应全部通过。

## 4. 运营商行业语义包（开箱即用）

启动时 `OperatorOntologySeeder` 幂等初始化以下内容，**不要求实施人员懂本体，也不依赖 LLM 现场生成本体**：

| 内容 | 说明 |
|---|---|
| 演示库 | 独立 MySQL 库 `luban_demo_operator`：`op_package / op_user / op_bill / op_complaint` 四表 + 近 6 个月演示数据（3 地市 12 区县、120 用户、约 600 账单、90 投诉） |
| 演示数据源 | 平台内注册「运营商演示库」，指向上述独立库 |
| 标准层概念 | 8 个概念：用户 / 套餐 / 月账单 / 投诉工单 + 指标（出账收入、投诉量、新增用户数、宽带用户数），含关系、预定义 JOIN、默认聚合与时间锚列。**概念描述不含任何表名列名**，跨省复用无需修改 |
| 方言词典 | 携转 / 离网 / 入网 / 地市 等运营商口语对照，挂在演示数据源的绑定集上，问数 prompt 注入 |
| 回归题集 | `backend/src/main/resources/ontology-questionsets/operator-semantics.json`，8 个典型问题，含概念命中 / SQL 落表 / 回答可用性结构断言 |

配置开关（`backend/src/main/resources/application.yml`）：

```yaml
luban:
  operator-package:
    enabled: true    # 置 false 整体关闭（其他行业部署互不影响）
```

注意：
- 演示库创建需要数据库账号有建库权限；无权限时语义包**自动跳过**（不阻断启动），日志有明确提示。
- 内置演示数据源的连接信息每次启动跟随平台当前配置重写——更换 `LUBAN_DATASOURCE_SECRET` 后无需手工修复，启动即自愈。
- 清理演示数据：删除 `luban_demo_operator` 库 + 平台内删除「运营商演示库」数据源 + 删除「运营商语义」概念域；配置关闭后重启不会重建。

### 语义包两层设计（各省表结构不同的解法）

- **标准层**（平台交付，跨省一致）：概念 / 关系 / 方言词典 / 回归题集，只描述业务语义与口径。
- **本地层**（每省现场生成）：概念 → 表列映射。演示库的映射随包预置；接入真实省库时由「绑定管理 → 自动绑定」（规则优先 + LLM 兜底）生成到各省真实表列上，标准层不动。

## 5. 密钥管理

`backend/start.sh` 首次运行自动生成并持久化到 `backend/.env`（已 gitignore，勿提交）：

| 环境变量 | 用途 |
|---|---|
| `LUBAN_JWT_SECRET` | 登录态签名；未注入时用随机临时密钥，重启后所有登录态失效 |
| `LUBAN_DATASOURCE_SECRET` | 数据源密码加密密钥；**换密钥后已有外部数据源需重新保存密码**，内置演示数据源自动重写 |
| `LUBAN_AGENT_AES_KEY` | 大模型 API Key 加密密钥 |
| `LUBAN_RSA_PRIVATE_KEY` | 传输层信封加密私钥（`backend/.rsa_key.pem` / `config/rsa-private.pem`） |

生产要求：以上密钥一律通过环境变量外部注入（或审核 start.sh 生成的 .env），严禁提交仓库；大模型 Key 用环境变量 `LUBAN_LLM_API_KEY / LUBAN_LLM_ENDPOINT / LUBAN_LLM_MODEL` 初始化默认 Agent 配置，或在「建模中心 → 大模型配置」填写。

## 6. 生产部署（真实省库接入路径）

1. **配置平台库**：生产 MySQL 的 `luban` 库 + 读写账号；设置 `luban.operator-package.enabled=false`（或保留演示库供培训）。
2. **注入密钥**：按第 5 节设置全部环境变量后 `./start.sh -d`。
3. **接入业务库**：建模中心 → 系统管理 → 添加 BOSS / 经分 / 客服等只读数据源（建议只读账号）。
4. **生成本地映射**：绑定管理 → 选择数据源 → 自动绑定；再到概念编辑器复核关键字段映射（金额、状态枚举、时间锚列）。
5. **本地化回归题集**：复制 `operator-semantics.json` 为 `operator-province-xxx.json`，把 `sqlContains` 断言改为本地表名（或仅保留概念命中断言），在「语义包回归」中验证——全部通过才交付业务用户。
6. **权限收敛**：按第 7 节授予角色权限，业务用户只给 `ask:read` / `workbench:read`。
7. **前端发布**：`npm run build` 产物（`frontend/dist`）交给 Nginx / 容器发布，API 反代到 8080。

## 7. 角色与权限基线

| 角色 | 关键权限 | 使用范围 |
|---|---|---|
| 平台管理员 | `people:*` 全部 + `connect:*` | 平台管理、建模中心 |
| 口径管理员（语义运营） | `connect:systems / connect:concepts / connect:concept-feedback` | 建模中心全部语义运营功能 |
| 应用开发者 | `apps:read` + 数据源权限 | 开发中心建模 |
| 业务用户 | `ask:read`、`workbench:read` | 智能问数、工作中心（本体不可见） |

概念级数据权限：平台管理 → 角色管理 → 概念域授权，控制角色可问的数据范围。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动日志「运营商语义包初始化失败」 | 数据库账号无建库权限。授权或置 `luban.operator-package.enabled=false` |
| 问数报「Embedding 服务不可用」降级 | 语义服务 8765 未启动或沙箱镜像构建失败，查看 `embedding-service/logs/server.log` |
| 更换 DATASOURCE_SECRET 后外部数据源连不上 | 预期行为：重新保存该数据源密码即可；内置演示数据源会自愈 |
| 问数命中不了概念 | 检查概念是否有该数据源的映射（概念编辑器 → 映射），或方言词典是否覆盖用户说法 |
| 登录态全部失效 | JWT 密钥变化（如未用 start.sh 而手工启动），统一用 start.sh 启动 |
| 300 秒超时 | 问数链路含多次 LLM 调用，确认大模型端点可用性与网络连通性 |
