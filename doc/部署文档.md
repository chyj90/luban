# 鲁班平台部署执行手册

> **用法**：拿起来按 1、2、3… 顺序执行，不要跳步。每个阶段末尾有 ✓ 检查点，检查点不通过先解决再往下走；文末《部署完成验收清单》全部勾选 = 部署完成。
> 架构说明、密钥细节、换省/换行业等参考内容在附录，主流程不需要阅读附录。

## 开始前：准备清单

**0.1 环境要求**

- [ ] 服务器：JDK 17+、Maven 3.8+、Node.js 18+、Python 3.10+（启用代码沙箱需 Docker）
- [ ] MySQL 8.x 已就绪（可远程；部署账号对该实例有建库权限）
- [ ] 网络互通：服务器 ↔ MySQL、服务器 ↔ 大模型 API、用户浏览器 ↔ 服务器

**0.2 向客户收集的信息（缺一项，对应步骤会被卡住）**

- [ ] 平台元数据库连接信息（host/端口/账号密码）
- [ ] 业务库清单及**只读账号**（运营商：BOSS/经分/客服库；写明每库的业务含义）
- [ ] 客户行业（决定阶段二走哪条分支）
- [ ] 组织架构（部门树，用于权限边界，如地市/区县）
- [ ] 业务人员常用口语说法样本（几十条即可，用于方言词典，如"携转""拉新"）

## 阶段一：安装平台（约 30 分钟，全行业通用）

1. **配置平台元数据库**：编辑 `backend/src/main/resources/application.yml` 的 `spring.datasource`（url/username/password）。库可不存在，连接串已带 `createDatabaseIfNotExist=true`。
2. **启动语义服务**（提供概念向量检索与代码沙箱）：
   ```bash
   cd embedding-service && pip install -r requirements.txt && ./start.sh -d
   ```
3. **启动后端**（自动生成并持久化密钥，见附录 B）：
   ```bash
   cd backend && ./start.sh -d
   ```
4. **启动前端**：开发验证用 `cd frontend && npm install && npm run dev`（5173）；正式交付用 `npm run build` 后发布 `dist/` 并反代 API 到 8080。
5. **登录验证**：浏览器打开平台地址，用超管账号登录（首次启动种子账号 **root / 123456**，登录后立即改密）。

✓ **检查点 1**
- [ ] 启动日志出现 `Started LubanApplication`
- [ ] 启动日志出现 `平台语义包就绪`（组织/人员/部门，全行业必有）
- [ ] 浏览器能登录进平台首页

## 阶段二：就位行业语义包（分叉点）

**判断：客户是什么行业？**

### 分支 A：客户是运营商（内置包，开箱即用）

1. 确认阶段一启动日志出现 `运营商语义包就绪：数据源「运营商演示库」→ 独立演示库 luban_demo_operator，概念 8 个`。
2. **保持 `luban.operator-package.enabled=true` 不要关**（生产也建议保留）：标准层概念与演示库一起就位，演示库不影响真实数据源，可作培训环境和回归基线。只有非运营商行业才关闭它。
3. 确认回归题集就位：建模中心 → 语义包回归 → 列表应出现「运营商语义包（8 用例）」。

→ 直接进入阶段三。

### 分支 B：客户是其他行业（平台当前**没有**内置该行业包）

**先弄包，再继续部署。** 按下列优先级三选一：

1. **向平台厂商索取行业语义包**（首选）：语义包交付物是"五件套"——行业 Seeder（概念+关系+映射骨架）、方言词典、回归题集 JSON、演示库结构、演示数据。厂商随平台版本内置交付，拿到含该行业包的平台版本后，按该版本说明启用（通常为 `luban.<行业>-package.enabled=true`）并重启。**弄完再进入阶段三。**
2. **自制语义包**（厂商未覆盖且交付周期不可接受时）：参照 `backend/src/main/java/com/luban/config/OperatorOntologySeeder.java` 实现行业五件套（概念描述**不得写死表名**，映射留给阶段三自动绑定；参照 `backend/src/main/resources/ontology-questionsets/operator-semantics.json` 编写回归题集）。开发-自测完成后随版本发布，再进入阶段三。
3. **降级路径：先部署后补包**（客户着急上线时）：不启用行业包，进入阶段三前先用 ConceptImportService（建模中心 → 概念导入）从客户的行业口径手册/文档导入概念，阶段三手工补映射。**注意**：此路径缺关系/词典/题集，问数命中率有限，属过渡方案，语义包到位后替换。

✓ **检查点 2**
- [ ] 分支 A：`运营商语义包就绪` 日志出现，回归列表有运营商题集
- [ ] 分支 B：所选路径的语义包已就位（启动日志/回归列表可见）；选降级路径的，已记录"补包计划"并告知客户

## 阶段三：接入客户数据源并与语义层对齐（核心，0.5–2 天）

> 本阶段目标：业务库的表列与语义层（概念→映射）对上，且用回归证明对上了。

1. **新建系统**：建模中心 → 系统管理 → 「新建系统」（填系统名/编码，如"BOSS核心"/"经分"）。一个源系统一条记录。
2. **新建数据源并测通**：选中该系统 → 「新建数据源」（类型选 MySQL 等，填 host/端口/库名/**只读账号**）→ 列表中点「测试连接」→ 状态变为**已连接**。逐库重复。
3. **自动绑定（映射生成）**：建模中心 → 绑定管理 → 对每个数据源执行**自动绑定**（规则优先 + LLM 兜底，后台任务自动轮询完成）。完成后查看绑定明细。
4. **人工复核关键映射**（自动绑定不等于正确，以下五类必须人工过目）：
   - 金额/数量类：单位、是否含税、正负号
   - 状态/类型枚举：在网/离网、已缴/未缴等枚举值与库中实际值一致
   - 时间锚列：指标用哪个时间字段归属账期/日（错一个，所有趋势都错）
   - JOIN 路径：概念间关联字段是否唯一、是否漏桥表
   - 组织字段：地市/区县/部门与平台组织架构对齐（权限依赖它）
5. **方言词典本地化**：绑定管理 → 该数据源绑定集 → 术语词典，把 0.2 收集的口语说法逐条配上概念（term/synonyms/conceptName）。
6. **概念域授权**：平台管理 → 角色管理 → 概念域授权，按"谁能看哪些业务数据"配好角色边界（如地市账号只授本地市域）。
7. **本地化回归题集**：复制 `backend/src/main/resources/ontology-questionsets/operator-semantics.json` 为 `operator-province-<省>.json`，把 `sqlContains` 断言改为客户真实表名（拿不准的可只保留 `mustHitConcepts`）。
8. **跑回归**：建模中心 → 语义包回归 → 运行本地化题集 → 查看报告。

✓ **检查点 3**
- [ ] 每个业务库状态"已连接"
- [ ] 自动绑定完成且第 4 步五类映射复核通过
- [ ] 回归报告 **100% 通过**；有失败 → 回到第 4/5 步修映射或词典，重跑直到全过

## 阶段四：开通用户并交付（约 0.5 天）

1. **建账号与角色**：平台管理 → 用户/组织（导入部门树）→ 角色分配（基线见附录 E）。
2. **业务用户视角验证**：用一名真实业务角色账号登录，确认只能看到「工作中心 + 智能问数」，问一个阶段三题集里的真实问题，回答正确且能看到口径来源。
3. **交付培训**（30 分钟即可）：业务用户教"怎么问、怎么标记坏答案"；口径管理员交代每周节奏（问题洞察 → 变更审核 → 跑回归）。

✓ **检查点 4**
- [ ] 业务角色账号问数命中概念、看不到语义运营菜单
- [ ] 口径管理员知晓每周运营节奏

## 附录 A：系统组成与数据边界

| 组件 | 技术 | 默认端口 | 说明 |
|---|---|---|---|
| 后端 | Spring Boot 3 / JPA | 8080 | 平台服务，含问数 agent、语义底座 |
| 前端 | React / Vite | 5173 (dev) | 生产构建为静态资源 |
| 语义服务 | Python | 8765 | 概念向量嵌入 + FAISS 检索 + 代码沙箱 |
| 平台元数据库 | MySQL 8.x | 3306 | `luban` 库，仅存平台元数据 |

数据边界：平台库只存平台元数据。业务数据（含演示数据）一律在外部库——运营商演示表在独立库 `luban_demo_operator`，与平台库物理解耦。

## 附录 B：密钥管理

`backend/start.sh` 首次运行自动生成并持久化到 `backend/.env`（已 gitignore，勿提交）：

| 环境变量 | 用途 |
|---|---|
| `LUBAN_JWT_SECRET` | 登录态签名；未注入时用随机临时密钥，重启后登录态全部失效 |
| `LUBAN_DATASOURCE_SECRET` | 数据源密码加密；**换密钥后外部数据源需重新保存密码**，内置演示数据源启动自愈 |
| `LUBAN_AGENT_AES_KEY` | 大模型 API Key 加密 |
| `LUBAN_RSA_PRIVATE_KEY` | 传输层信封加密私钥 |

生产要求：一律环境变量外部注入（或审核 start.sh 生成的 .env）；大模型 Key 用 `LUBAN_LLM_API_KEY / LUBAN_LLM_ENDPOINT / LUBAN_LLM_MODEL` 初始化，或在「建模中心 → 大模型配置」填写。

## 附录 C：运营商语义包明细与清理

启动时 `OperatorOntologySeeder` 幂等初始化：独立演示库（`op_package/op_user/op_bill/op_complaint` + 3 地市 12 区县 120 用户近 6 个月数据）、演示数据源、8 个标准层概念（**描述不含表名**，跨省复用）、运营商方言词典、8 用例回归题集。配置开关 `luban.operator-package.enabled`。

语义包两层设计（各省表结构不同的解法）：**标准层**（概念/关系/词典/题集骨架，跨省一致随平台交付）+ **本地层**（概念→表列映射，阶段三自动绑定现场生成）。

清理演示数据：删除 `luban_demo_operator` 库 + 平台内删除「运营商演示库」数据源与「运营商语义」概念域；配置关闭后重启不会重建。

## 附录 D：已部署之后——换省 / 换行业 / 换库

> 核心原则：**标准层随软件走，本地层不带走。**

**换省公司（同行业新客户）**：
- 自动获得：标准层骨架（种子）、平台语义包、演示语义。带不走也不该带走：表列映射、方言本地化、组织权限、问数历史。
- 全新环境（推荐）：重走本手册阶段一→四（映射与词典按新省现场生成）。
- 原环境重置：备份并清空平台库、删除旧省业务库与演示库 → 重启种子自重建 → 从阶段二第 2 步继续。
- 旧省下线：导出审计数据（变更台账、回归报告）后连库回收。

**换行业**：在换省步骤之上增加——
1. 关闭旧行业包（`luban.operator-package.enabled=false`）
2. 清理语义残留：删除旧行业演示数据源、概念域、演示库、题集 JSON
3. 归档 `agent_query_log` 旧概念引用（否则健康度统计失真）
4. 已固化查询不受影响（SQL 文本不依赖概念运行时）
5. 按阶段二分支 B 部署新行业包 → 重走阶段三、四
6. 平台语义（组织/人员/部门）任何行业都保留

**省内换库/表结构变更**：接新库 → 绑定管理重新自动绑定并复核 → 更新本地化题集表名断言 → 回归通过交付。业务用户口径不变、无感。

## 附录 F：常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 日志「运营商语义包初始化失败」 | 数据库账号无建库权限：授权，或 `luban.operator-package.enabled=false` 跳过 |
| 问数报「Embedding 服务不可用」降级 | 语义服务 8765 未启动或沙箱镜像构建失败，看 `embedding-service/logs/server.log` |
| 换 DATASOURCE_SECRET 后外部数据源连不上 | 重新保存该数据源密码即可；内置演示数据源自愈 |
| 自动绑定结果大量为空 | 概念与客户表差异过大：先人工补核心概念的映射，再跑绑定收敛 |
| 回归用例失败 | 看报告里失败的断言类型：概念未命中→补词典；SQL 落表错→修映射；回答不可用→查数据与权限 |
| 问数 300 秒超时 | 大模型端点可用性/网络连通性排查 |
| 登录态全部失效 | JWT 密钥变化（未用 start.sh 手工启动），统一用 start.sh |
