## 一、场景概述

离散制造业排产是一个**约束满足 + 优化**问题。在调用排产算法前，必须通过 10 项前置检验（P1~P10），任何一项不通过就不调用算法，而是返回具体原因。

前置检验由**本体推导**实现：ContextBuilder 沿 `INPUT_OF → Concept → DERIVED_FROM` 链路展开，将 `PRE_CHECK[P1]~PRE_CHECK[P10]` 指令注入 Agent prompt，LLM 执行 nl2sql 查询并判断。

### 排产前置检验清单

| 编号 | 检验项 | 检验内容 | 失败影响 |
|:--:|------|------|------|
| P1 | 工作中心存在性 | 指定产线/工作中心在系统中是否存在 | 排产无执行主体 |
| P2 | 工作中心可用性 | 产线当前是否在运行（非停机/维修/封存状态） | 无法排产 |
| P3 | 额定产能 > 0 | 工作中心的日额定产能是否为正数 | 算法除零或无意义 |
| P4 | BOM 存在性 | 产品是否有 BOM 定义 | 不知道用什么料 |
| P5 | 工艺路线存在性 | 产品是否有工艺路线（至少 1 道工序） | 不知道在哪加工 |
| P6 | 物料齐套率 | BOM 展开后所有子项的可用库存是否满足生产数量 | 缺料无法开工 |
| P7 | 已排产负荷 | 工作中心已排产数量 + 新订单数量 ≤ 日产能 × 排产天数 | 产能不足 |
| P8 | 交期可达性 | 最早开工日 + 生产周期 ≤ 客户交期 | 无法按时交付 |
| P9 | 设备可用率 | 关键工作中心的主设备可用率 ≥ 80% | 设备故障风险高 |
| P10 | 在制订单冲突 | 同一工作中心是否有未完工的在制订单与新订单工序冲突 | 工序干涉 |

### 步骤 0：导入测试数据

```bash

# 2. 导入排产示例数据（工作中心、BOM、工艺路线、生产订单、库存、设备）
```

#### E2E-01 注册排产算法

1. 打开浏览器，进入 Luban 管理后台
2. 左侧菜单点击 **系统管理** → 选择已创建的制造系统 → 进入 **工具管理** 页面
3. 点击右上角 **「+ 新建」** 按钮
4. 在弹出的表单中填写：
   - **工具名称**：`排产可行性评估`
   - **显示名称**：`排产可行性评估`
   - **类型**：下拉选择 `ALGORITHM`（列表中应出现 ALGORITHM 选项）
   - **描述**：`离散制造业排产可行性评估，基于工作中心产能/BOM/工艺路线等约束进行排产优化求解`
5. 类型选择 ALGORITHM 后，表单会展开**算法脚本配置**区域：
