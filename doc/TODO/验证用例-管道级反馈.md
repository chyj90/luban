### 用例 0：准备基础数据

**目的**：导入制造行业 ERP 本体 + 自动映射概念到数据源，为后续用例提供数据基础。

#### 0.1 导入行业本体（SQL 脚本）

| 步骤 | 操作 |
|------|------|
| 1 | 执行 `mysql -u root -p luban < backend/sql/init-manufacturing-erp-ontology.sql` |
| 2 | 确认输出验证结果 |

**预期结果**：
- 行业 `manufacturing_erp`（制造行业ERP）创建成功
- 7 个领域：基础域、财务域、采购域、销售域、生产域、人力域、设备域
- 58 个概念、98 条关系、3 种自定义关系类型（PRODUCES/CONSUMES/FLOWS_TO）

**验证**：
```sql
SELECT 'industry' AS tbl, COUNT(*) AS cnt FROM industry WHERE name = 'manufacturing_erp'
UNION ALL
SELECT 'ontology_group', COUNT(*) FROM ontology_group WHERE industry_id = (SELECT id FROM industry WHERE name = 'manufacturing_erp')
UNION ALL
SELECT 'concept', COUNT(*) FROM concept WHERE group_id IN (SELECT id FROM ontology_group WHERE industry_id = (SELECT id FROM industry WHERE name = 'manufacturing_erp'))
UNION ALL
SELECT 'concept_relation', COUNT(*) FROM concept_relation WHERE source_concept_id IN (SELECT id FROM concept WHERE group_id IN (SELECT id FROM ontology_group WHERE industry_id = (SELECT id FROM industry WHERE name = 'manufacturing_erp')));
```

**预期计数**：industry=1, ontology_group=7, concept=58, concept_relation=98

#### 0.4 自动映射概念到表结构

> **说明**：SQL 脚本只创建了概念和关系，**没有** `concept_mapping` 和 `concept_join_mapping`。需要通过概念编辑器的「自动映射」功能，让 LLM 根据概念描述和数据源表结构自动生成映射。

| 步骤 | 操作 |
|------|------|
| 1 | 进入概念编辑页面（ConceptEditorPage），选择行业"制造行业ERP" |
| 2 | 点击「自动映射」按钮 |
| 3 | 在弹出的概念选择弹窗中，勾选需要映射的概念（默认选中所有未映射概念） |
| 4 | 点击"下一步"，选择数据源 `${DATASOURCE_ID}` |
| 5 | 点击"开始映射"，等待异步任务完成 |
| 6 | 查看映射结果，确认置信度 ≥ 0.7 的映射 |
| 7 | 点击"应用映射"，确认写入 `concept_mapping` 和 `concept_join_mapping` |

**预期结果**：
- 自动映射任务提交成功，返回 `taskId`
- LLM 根据概念描述（如"营收：企业经营活动产生的收入总额，由SD开票汇总而来"）匹配到数据源表字段（如 `billing.net_value`）
- `concept_mapping` 表写入映射记录，`is_auto = TRUE`
- `concept_join_mapping` 表写入 JOIN 映射（如 营收→开票 的 JOIN 条件）

**验证**：
```sql
-- 检查映射数量
SELECT COUNT(*) AS mapping_count FROM concept_mapping WHERE is_auto = TRUE;
-- 检查 JOIN 映射数量
SELECT COUNT(*) AS join_count FROM concept_join_mapping;
-- 抽查关键概念的映射
SELECT c.name, cm.table_name, cm.column_name, cm.confidence
FROM concept c
JOIN concept_mapping cm ON c.id = cm.concept_id
WHERE c.name IN ('营收', '销售金额', '利润', 'OEE', '离职率')
ORDER BY c.name;
```

> **如果自动映射不可用**（数据源无 ERP 表结构），可手动映射核心概念：
>
> | 概念 | 表名 | 字段名 | 映射类型 |
> |------|------|--------|----------|
> | 营收 | billing | net_value | direct |
> | 销售金额 | billing | net_value | direct |
> | 利润 | profit_center | profit_amount | direct |
> | 成本 | cost_center | cost_amount | direct |
> | 销售订单 | sales_order | order_number | direct |
> | 客户 | customer | customer_name | direct |
> | OEE | production_oee | oee_value | direct |
> | 离职率 | hr_turnover | turnover_rate | direct |

**验证 SQL**：
```sql
SELECT id, feedback_type, status, user_description,
       pipeline_id IS NOT NULL AS has_pipeline_ref,
       llm_analysis IS NULL AS no_llm_yet
FROM concept_feedback
WHERE session_id = '${SESSION_ID}'
ORDER BY created_at DESC LIMIT 1;
```

> **关键验证点**：`llm_analysis IS NULL` 必须为 `true`（提交时不触发 LLM，管理员查看时才触发）。`pipeline_id` 引用 `pipeline_trace` 表，管道数据通过 JOIN 获取，不存副本。对话历史通过 `session_id` 实时查消息表，不冗余存储。
