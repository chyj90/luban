## 三、集成测试用例

### 3.1 Agent 路由

| 编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 |
|:--:|------|------|------|------|
| IT-01 | LLM 正确输出 algorithm action | 算法已绑定概念，prompt 含算法列表 | 用户问"下周三号线接不接得了 5000 件订单" | LLM 先 nl2sql 查数据，再输出 type='algorithm' |
| IT-02 | routeByType 正确路由 algorithm | LLM 输出 type='algorithm' | routeByType 收到 type='algorithm' | 调用 routeAlgorithm()，data 中 next_action='algorithm' |
| IT-03 | algorithm_executor 正确执行 | pending_algorithm 含算法名和 input_data | Graph 路由到 algorithm_executor | 执行脚本，返回结果给 LLM |
| IT-04 | algorithm_executor 执行后返回 agent | 算法执行完毕 | data.next_action='continue' | Graph 路由回 agent 节点 |
| IT-05 | 算法不存在时的降级 | LLM 调用不存在的算法名 | algorithm_executor 查找算法失败 | 返回错误消息给 LLM，LLM 降级到 CODE_MODE |
| IT-06 | 算法脚本执行失败降级 | 算法脚本有语法错误 | algorithm_executor 执行失败 | 返回 stderr 给 LLM，LLM 降级到 CODE_MODE |
| IT-07 | 非算法场景不调用算法 | 用户问"今天天气怎么样" | LLM 推理 | 不输出 algorithm action，走 final_answer |

## 五、边界与异常测试用例

| 编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 |
|:--:|------|------|------|------|
| EX-01 | 算法未绑定任何概念 | 算法已注册但未绑定概念 | 用户问"下周三号线接不接得了 5000 件" | LLM 不发现该算法，走 CODE_MODE 或 nl2sql+final_answer |
| EX-02 | 算法脚本文件不存在 | 算法注册了但 scriptPath 指向的文件不存在 | 用户触发算法调用 | algorithm_executor 返回错误，LLM 收到错误后降级到 CODE_MODE |
| EX-03 | 算法执行超时 | 算法脚本有死循环或长时间运行 | 用户触发算法调用 | 30 秒超时，返回超时错误，LLM 降级到 CODE_MODE |
| EX-04 | 算法输出格式不符合 schema | 算法输出了非 JSON 或缺少字段 | 算法执行完毕 | 返回错误，LLM 尝试重新解析 |
| EX-05 | 同一概念绑定多个算法 | 概念"订单量"绑定了排产算法和订单预测算法 | 用户问"下周三号线接不接得了 5000 件" | LLM 选择排产算法（更匹配"接不接得了"的语义） |
| EX-06 | 算法输入数据不足 | 算法需要 5 个参数，但 SQL 只查了 3 个 | 用户触发算法调用 | LLM 发现参数不足，自动补查 SQL |
| EX-07 | 算法执行过程中用户中断 | 算法正在执行 | 用户点击"停止"或在对话中发送新消息 | 算法执行被中断，返回中断状态 |
| EX-08 | 并发调用同一算法 | 两个用户同时触发同一算法 | 用户 A 和 B 同时问排产问题 | 各自独立执行，互不影响 |
| EX-09 | 算法脚本有安全风险 | 算法脚本包含 `os.system('rm -rf /')` | 算法执行 | 沙箱隔离，系统不受影响，返回错误 |
| EX-10 | 超大输入数据 | SQL 返回 100 万行数据，传给算法 | 用户触发算法调用 | 算法执行成功或超时，不会 OOM |
