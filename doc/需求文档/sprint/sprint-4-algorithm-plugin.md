# Sprint 4：算法插件框架

> **状态：🔴 待审阅** | **周期：2 周** | **目标：外部算法注册 → 数据供给 → 结果回写，跑通排产场景**

---

## 一、Sprint 目标

让外部算法服务（如排产算法、预测模型）能注册到鲁班，鲁班提供数据供给和结果回写能力。

**关键验收标准：**

| # | 场景 | 操作 | 预期结果 |
|---|------|------|---------|
| 1 | 算法注册 | 在控制台注册一个排产算法服务 | 注册成功，状态显示"在线" |
| 2 | 数据供给 | 算法插件请求查询订单、BOM、设备数据 | 鲁班并行聚合数据，3 秒内返回完整数据集 |
| 3 | 结果执行 | 算法插件回传排产结果 | 鲁班自动调用工具执行结果 |
| 4 | 人工确认 | 配置"排产更新"为需确认动作 | 算法回传后进入待确认队列，管理员确认后才执行 |
| 5 | 贪心示范插件 | 部署贪心排产示例容器，配置指向鲁班 | 通过对话触发排产，端到端跑通 |

## 二、需求列表

### 2.1 算法插件注册

**优先级：P0**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 插件注册 | 注册算法插件（名称、描述、地址、鉴权方式） |
| 2 | 健康检查 | 定期检查插件是否在线 |
| 3 | 插件配置 | 配置插件需要的输入/输出数据格式 |
| 4 | 插件控制台 | 插件列表、状态监控、启用/禁用 |

### 2.2 数据供给 API

**优先级：P0**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 数据请求 | 算法插件向鲁班请求数据（指定数据源和查询条件） |
| 2 | 并行聚合 | 多数据源并行查询，聚合返回 |
| 3 | 数据格式 | 统一 JSON 格式，支持分页 |
| 4 | 超时控制 | 默认 30 秒，超时返回部分结果 |

### 2.3 结果回写

**优先级：P0**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 结果回写 API | 算法插件回传执行结果，鲁班存入数据库 |
| 2 | 工具调用 | 回写结果可触发工具调用（如更新排产、创建工单） |
| 3 | 人工确认 | 配置某些操作为"需人工确认"，回写后进入待确认队列 |
| 4 | 确认通知 | 人工确认项通过通知提醒管理员 |

### 2.4 贪心排产示范插件

**优先级：P1**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 贪心算法 | 基于贪心策略的排产算法（最早开始时间优先） |
| 2 | 数据源 | 订单数据、BOM（物料清单）、设备可用性 |
| 3 | 结果 | 排产计划（每个订单的开始时间、结束时间、分配设备） |
| 4 | Docker 部署 | 独立的 Docker 容器，通过 API 与鲁班通信 |
