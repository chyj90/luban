## 二、需求列表

### 2.1 AI 工具编排引擎（DAG 引擎）

**优先级：P0**

新建轻量 DAG 执行引擎，支持将多个 MCP 工具串成有向无环图自动执行。

**与现有审批流程引擎的关系：**

| | AI 工具编排引擎（Sprint 3 新建） | 人审批流程引擎（现有） |
|------|------|------|
| 节点类型 | MCP 工具调用 | 审批/条件/抄送 |
| 执行方式 | 自动执行 | 等待人操作 |
| 编排方式 | AI 生成 / 手动配置 | 拖拽设计器 |
| 数据流 | 变量自动映射 | 表单字段传递 |
| 典型场景 | 查状态→建工单→通知 | 请假→领导批→归档 |
| 引擎 | 轻量 DAG，内存执行 | ProcessEngine（JPA） |

两者互不依赖，独立演进。未来可通过「人工确认节点」桥接。

**代码结构：**

```
com/luban/dag/
├── DagEngine.java              # DAG 执行引擎
├── DagDefinition.java          # DAG 定义（JSON 存储节点和边）
├── DagNode.java                # 节点定义
│   ├── nodeId: String
│   ├── toolName: String        # 关联的 ToolDefinition.name
│   ├── inputMapping: JSON      # 输入参数映射
│   ├── outputMapping: JSON     # 输出结果映射
│   └── condition: String       # 条件表达式
├── DagEdge.java                # 边定义
│   ├── sourceNodeId: String
│   ├── targetNodeId: String
│   └── condition: String       # 条件边（if/else）
├── DagContext.java             # 执行上下文（变量池）
└── DagExecutor.java            # 拓扑排序 + 并行执行 + 结果收集
```

**执行流程：**

```
1. 加载 DAG 定义（JSON）
2. 拓扑排序，确定执行顺序
3. 按层级并行执行（同层节点可并行）
4. 每个节点：
   a. 从 DagContext 读取输入变量
   b. 调用 ToolDefinition 对应的执行器
   c. 将输出写入 DagContext
5. 条件边：根据节点输出决定下一跳
6. 全部完成 → 返回 DagContext 中的所有变量
```

**DAG 定义 JSON 示例：**

```json
{
  "id": "device_fault_closure",
  "name": "设备故障闭环",
  "nodes": [
    {
      "nodeId": "check_status",
      "toolName": "query_device_status",
      "inputMapping": {"device_id": "{{trigger.device_id}}"},
      "outputMapping": {"status": "{{result.status}}", "is_fault": "{{result.status == 'FAULT'}}"}
    },
    {
      "nodeId": "create_order",
      "toolName": "create_work_order",
      "inputMapping": {"device_id": "{{trigger.device_id}}", "issue": "{{check_status.result.error_message}}"},
      "outputMapping": {"order_id": "{{result.id}}"}
    },
    {
      "nodeId": "notify",
      "toolName": "send_notification",
      "inputMapping": {"order_id": "{{create_order.order_id}}", "device_id": "{{trigger.device_id}}"}
    }
  ],
  "edges": [
    {"source": "check_status", "target": "create_order", "condition": "{{check_status.is_fault}}"},
    {"source": "create_order", "target": "notify"}
  ]
}
```

**功能点：**

| # | 功能 | 说明 |
|---|------|------|
| 1 | DAG 定义 CRUD | 创建/编辑/删除 DAG 定义 |
| 2 | DAG 执行 | 加载定义 → 拓扑排序 → 按层并行执行 |
| 3 | 变量映射 | 节点间数据自动传递（inputMapping/outputMapping） |
| 4 | 条件分支 | 根据节点输出决定是否执行下游节点 |
| 5 | 并行执行 | 同层无依赖节点并行执行 |
| 6 | 超时控制 | 整个 DAG 超时时间可配置（默认 5 分钟） |
| 7 | 错误处理 | 节点失败时可配置：终止/跳过/重试 |
| 8 | AI 生成 DAG | Agent 根据自然语言描述自动生成 DAG 定义 |
| 9 | DAG 控制台 | 可视化查看 DAG 结构和执行状态 |

### 2.2 NL2SQL 自然语言查询

**优先级：P0**

用户用自然语言提问，LLM 根据表结构自动生成 SQL 并执行。

**技术方案：**

```
用户输入："昨天 3 号车间产量"
      │
      ▼
鲁班 Agent 意图识别 → 判断为「数据查询」
      │
      ▼
LLM 根据表结构（Datasource Schema）生成 SELECT SQL
      │
      ▼
SQL 执行器（复用现有 Query 体系）→ 返回结果
      │
      ▼
LLM 将结果转为自然语言回复
```

**不需要预置问答模板**，大模型直接生成 SQL。优点是灵活，用户问什么都能查，不局限于预设问题。

**功能点：**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 表结构注入 | 将可用 Datasource 的表结构注入 LLM 上下文 |
| 2 | SQL 生成 | LLM 根据表结构 + 用户问题生成 SELECT 语句 |
| 3 | SQL 安全校验 | 只允许 SELECT，拒绝写操作，限制行数 |
| 4 | 结果转自然语言 | LLM 将查询结果转为用户可理解的自然语言 |
| 5 | 错误重试 | SQL 执行失败时，LLM 修正 SQL 后重试（最多 3 次） |
| 6 | 结果可视化 | 数据结果自动适配图表（趋势图/柱状图/表格） |

### 2.3 归因分析

**优先级：P1**

支持"为什么 X 下降了/上升了"类问题，结合企业知识图谱 + LLM 推理链，自动多维度交叉分析。

**技术方案：**

```
用户问："为什么本周良率下降了"
      │
      ▼
LLM 拆解分析维度（时间、产线、班组、物料、设备...）
      │
      ▼
企业知识图谱提供维度关系（产线→设备→班组→物料→供应商）
      │
      ▼
LLM 推理链：逐维度查询 → 对比 → 排除 → 定位根因
      │
      ▼
生成归因报告（结论 + 证据链 + 建议）
```

**功能点：**

| # | 功能 | 说明 |
|---|------|------|
| 1 | 知识图谱构建 | 从 Datasource 表结构自动构建实体关系图 |
| 2 | 维度拆解 | LLM 分析问题，拆解为多维度查询 |
| 3 | 逐维查询 | 每个维度执行一次 NL2SQL 查询 |
| 4 | 交叉分析 | 对比各维度数据，排除无关因素，聚焦异常维度 |
| 5 | 推理链 | LLM 逐步推理，每一步都有数据支撑 |
| 6 | 归因报告 | 生成结构化的归因报告（结论、证据链、建议） |

**与 NL2SQL 查询的关系：**

- NL2SQL 查询：单次自然语言查询，返回数据
- 归因分析：多次 NL2SQL 查询 + 推理链，返回根因分析
