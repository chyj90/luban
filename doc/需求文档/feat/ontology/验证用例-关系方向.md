## 用例 0：准备基础数据

**目的**：创建行业、领域和概念，为后续用例提供数据基础。

### 0.1 创建行业

**步骤**：
1. 进入行业管理页面（OntologyGroupPage）
2. 点击"新增行业"
3. 填写：
   - 名称：`manufacturing`
   - 显示名称：`智能制造`
   - 描述：`智能制造行业本体`
4. 保存

**预期结果**：
- 行业创建成功
- 自动生成 9 种内置关系类型（DRILLS_INTO、COMPUTED_FROM 等）
- 展开该行业，关系列表可见 9 条内置关系，每条的「方向」列显示起点角色→终点角色

**验证**：
```sql
SELECT id, name, display_name FROM industry;
SELECT relation_type, label, source_role, target_role, source_to_target
FROM industry_relation WHERE industry_id = <行业ID> ORDER BY sort_order;
```

### 0.2 创建本体组（领域）

**步骤**：
1. 进入行业管理页面
2. 展开"智能制造"行业，点击"新增领域"
3. 填写：
   - 名称：`production_metrics`
   - 显示名称：`生产指标`
   - 描述：`生产相关指标本体`
   - 行业：选择"智能制造"
4. 保存

**预期结果**：
- 领域创建成功，绑定到智能制造行业

**验证**：
```sql
SELECT id, name, display_name, industry_id FROM ontology_group;
```

### 0.3 创建概念

**步骤**：
1. 进入概念编辑页面（ConceptEditorPage），选择领域"生产指标"
2. 依次创建以下概念：

| 概念名 | 描述 | 父概念 |
|--------|------|--------|
| `OEE` | 设备综合效率，综合衡量设备利用率、性能和质量的指标 | 无 |
| `可用率` | 设备实际运行时间占计划运行时间的比例 | OEE |
| `性能率` | 设备实际生产速度占理论速度的比例 | OEE |
| `质量率` | 合格品数量占总生产数量的比例 | OEE |

3. 创建方式：
   - **方式一（前端按钮）**：在「生产指标」域下，点击「+ 新建概念」→ 输入名称，概念自动绑定到当前域
   - **方式二（LLM）**：在聊天框输入 `帮我创建概念：OEE=设备综合效率，可用率、性能率、质量率作为OEE的子概念，所属领域为production_metrics`

**预期结果**：
- 4 个概念创建成功
- OEE 为根概念，可用率、性能率、质量率为其子概念（通过 `parentId` 建立父子层级，前端渲染为包含关系连线，不存储为 `concept_relation` 记录）
- 概念间的真实关系：OEE → 可用率、OEE → 性能率、OEE → 质量率，选择「计算得出」（`COMPUTED_FROM`，OEE 由这三个因子计算得出），存入 `concept_relation` 表
- 画布中可见树形层级结构

**验证**：
```sql
SELECT id, name, parent_id, group_id FROM concept ORDER BY id;
```

### 0.4 创建数据源并导入测试数据

**目的**：为「智能制造」行业创建数据源，使概念能关联到实际的数据库表/字段，LLM 生成本体时才能选择数据源和关联字段。

**步骤**：

1. **建库建表**：
   ```bash
   mysql -u root -p < sql/init-manufacturing-schema.sql
   ```
   创建 `manufacturing_db` 数据库，包含 3 张表：
   - `production_lines`：产线信息（3 条产线）
   - `production_metrics`：生产指标明细（按日 + 产线，含原始数据和计算结果）
   - `production_downtime`：停机记录（用于下钻分析）

2. **导入 Mock 数据**：
   ```bash
   mysql -u root -p < sql/init-manufacturing-data.sql
   ```
   导入 3 条产线 × 30 天的生产指标数据，含正常波动和异常场景。

3. **注册数据源**：
   进入数据源管理页面，点击「新增数据源」：
   - Slug：`manufacturing`
   - 名称：`智能制造生产数据`
   - 类型：`MySQL`
   - 配置：
     ```json
     {
       "host": "localhost",
       "port": 3306,
       "database": "manufacturing_db",
       "username": "root",
       "password": "your_password"
     }
     ```
4. 点击「测试连接」，确认连接成功后保存

**预期结果**：
- 数据源创建成功，状态为 `connected`
- 后续 LLM 生成本体、创建概念映射时，可以选择此数据源的表和字段
- 概念映射（`concept_mapping`）可关联到 `production_metrics` 表的字段：
  | 概念 | 映射表 | 映射字段 |
  |------|--------|---------|
  | OEE | production_metrics | oee |
  | 可用率 | production_metrics | availability |
  | 性能率 | production_metrics | performance |
  | 质量率 | production_metrics | quality |

**验证**：
```sql
SELECT id, slug, name, type, status FROM datasources;
```

## 用例 2：LLM 生成本体时正确填入方向和公式

**目的**：验证 LLM 看到带方向的关系描述后，能正确创建 `COMPUTED_FROM` 关系，且公式自动补充到兄弟关系。

### 2.1 创建第一批关系（带公式）

**步骤**：
1. 在聊天框输入：`帮我创建概念关系：OEE 由可用率、性能率和质量率计算得出，公式为 OEE = 可用率 × 性能率 × 质量率`
2. 观察 LLM 输出的 `ontology_action`
3. 确认关系创建后，检查 `concept_relation` 表中数据

**预期结果**：
- LLM 输出 3 条 `ADD_RELATION`，每条都带 `expression` 字段
- 第一条创建时，后两条尚未存在，无兄弟可补充
- 第二条创建时，第一条已有 expression（相同），跳过
- 第三条创建时，前两条已有 expression（相同），跳过
- 最终 3 条关系 expression 均为 `OEE = 可用率 × 性能率 × 质量率`

**验证 SQL**：
```sql
SELECT c1.name AS source, c2.name AS target, r.relation_type, r.expression
FROM concept_relation r
JOIN concept c1 ON r.source_concept_id = c1.id
JOIN concept c2 ON r.target_concept_id = c2.id
WHERE r.relation_type = 'COMPUTED_FROM';
```
预期：source 全是 OEE，target 分别是可用率/性能率/质量率，expression 全相同。

### 2.2 验证公式已写入 LLM Prompt

**步骤**：
1. 在聊天框输入：`OEE 是多少？`
2. 观察 LLM 收到的 prompt（日志或调试输出）

**预期结果**：
- Prompt 中包含「## 计算关系（COMPUTED_FROM/DERIVED_FROM）」section
- 包含 `OEE = 可用率 × 性能率 × 质量率`
- 包含「必须严格按照公式计算，禁止自行编造公式」

## 用例 4：Jena 推理机正确处理 COMPUTED_FROM 传递性

**目的**：验证 `COMPUTED_FROM` 的传递性推理。

**步骤**：
1. 在用例 0.3 的基础上，再新增一个概念：`设备开动率`（描述：设备实际开动时间占可用时间的比例）
2. 创建关系：`可用率 --COMPUTED_FROM--> 设备开动率`，公式：`可用率 = 设备开动率`
3. 查询 OEE 的关联概念

**预期结果**：
- Jena 推理出 `OEE --COMPUTED_FROM--> 设备开动率`（传递性：OEE→可用率→设备开动率）
- 查询 OEE 的相关概念时，设备开动率出现在结果中

**验证 SQL**：
```sql
-- 确保关系链正确，且公式已落库
SELECT c1.name AS source, c2.name AS target, r.relation_type, r.expression
FROM concept_relation r
JOIN concept c1 ON r.source_concept_id = c1.id
JOIN concept c2 ON r.target_concept_id = c2.id
WHERE r.relation_type = 'COMPUTED_FROM'
ORDER BY c1.name, c2.name;
```
预期输出：
```
source | target    | relation_type | expression
-------|-----------|--------------|---------------------------
OEE    | 可用率     | COMPUTED_FROM | OEE = 可用率 × 性能率 × 质量率
OEE    | 性能率     | COMPUTED_FROM | OEE = 可用率 × 性能率 × 质量率
OEE    | 质量率     | COMPUTED_FROM | OEE = 可用率 × 性能率 × 质量率
可用率  | 设备开动率 | COMPUTED_FROM | 可用率 = 设备开动率
```

## 用例 5：问数时 LLM 正确理解 COMPUTED_FROM 方向和公式

**目的**：验证 LLM 在查询阶段能正确解释 `COMPUTED_FROM` 关系，并按公式计算。

### 5.1 方向验证

**步骤**：
1. 确保 OEE 和可用率、性能率、质量率的关系已正确创建（用例 2 完成）
2. 在聊天框输入：`OEE 下降的原因是什么？`
3. 观察 LLM 的回答

**预期结果**：
- LLM 的思考过程或回答中，提到"OEE 由可用率、性能率和质量率计算得出，公式为 OEE = 可用率 × 性能率 × 质量率"
- LLM 会调用 get_availability、get_performance、get_quality 三个工具获取数据
- LLM 按公式计算：OEE = 可用率 × 性能率 × 质量率
- 不会出现"可用率由 OEE 计算得出"这种方向错误

### 5.2 公式计算验证

**步骤**：
1. 在聊天框输入：`OEE 是多少？`
2. 观察 LLM 是否调用了三个工具的 API，并按公式计算

**预期结果**：
- LLM 调用了可用率、性能率、质量率对应的工具
- LLM 给出的答案是基于公式计算的结果，而非凭空编造

## 用例 7：前端关系类型所有方向正确

**目的**：遍历所有内置关系，验证前端连线方向正确。

**步骤**：
1. 在概念编辑器中，对每种内置关系分别连线
2. 检查 `concept_relation` 表中的 source/target 是否正确

**关系方向对照表**：

| 关系 | 用户拖线方向 | API 应存储 | sourceToTarget |
|---|---|---|---|
| DRILLS_INTO | 父→子 | source=子, target=父 | false |
| DRILLED_FROM | 子→父 | source=父, target=子 | false |
| CORRELATED | A→B（双向） | source=B, target=A | false |
| INVOKES | 概念→算法 | source=概念, target=算法 | true |
| INPUT_OF | 算法→概念 | source=算法, target=概念 | true |
| OUTPUT_OF | 概念→算法 | source=概念, target=算法 | true |
| COMPUTED_FROM | 计算结果→计算因子 | source=结果, target=因子 | true |
| DERIVED_FROM | 派生结果→派生条件 | source=结果, target=条件 | true |
| EQUIVALENT_TO | A→B（双向） | source=B, target=A | false |
