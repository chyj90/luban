## 一、背景

### 1.1 现状

当前鲁班平台已完成「一、自动洞察（查数 → 懂数）」的核心能力建设：

- **NL2SQL**：用户自然语言 → FAISS 向量检索 → 概念匹配 → 本体展开 → LLM 推理 → SQL 生成/执行
- **CODE_MODE**：LLM 可生成 Python 代码（pandas/numpy），通过 `/v1/execute-code` 端点执行，支持传入 `input_data`（SQL 查询结果），实现复杂数据分析
- **下钻引擎**：DRILLS_INTO 关系定义维度下钻路径，LLM 自动多轮下钻分析
- **关联维度**：CORRELATED 关系交叉验证，排除干扰因素
- **异常阈值**：概念级别的 anomalyThresholdExpr，自动触发异常检测

### 1.2 问题

CODE_MODE 虽然支持 LLM 生成 Python 代码做数据分析，但存在以下局限：

| 问题 | 影响 | 严重度 |
|:--:|------|:--:|
| LLM 生成的代码不可靠 | 复杂算法可能出错，需人工验证 | 🟠 高 |
| 无法复用企业已有算法 | 已投入的算法资产无法接入 | 🔴 严重 |
| 无算法版本管理 | 算法更新后旧链路不可追溯 | 🟡 中 |
| 算法发现靠文本匹配 | 用户不知道有哪些算法，LLM 依赖描述匹配 | 🟠 高 |

### 1.3 目标

将「三、算法热加载（LLM + 企业算法编排）」与「一、自动洞察」结合，通过本体驱动算法发现与编排，实现企业决策场景落地。

**核心思路**：算法作为"本体感知的工具"注册到概念知识图谱中，复用 CODE_MODE 的 Python 执行通道，LLM 通过概念关系（INVOKES/INPUT_OF/OUTPUT_OF）自动发现并调用算法，输出可解释的决策建议。

## 二、需求范围

### 2.1 本次需求（Phase 1：算法注册 + 本体绑定 + Agent 编排）

**目标**：支持算法注册、本体绑定、LLM 自动编排调用，覆盖 5 个验证场景。

**功能清单**：

| 编号 | 功能 | 说明 |
|:--:|------|------|
| F1 | 算法注册 | 算法作为 ToolDefinition（type='ALGORITHM'）注册，支持上传 Python 脚本 |
| F2 | 本体绑定 | 算法通过 ToolConcept（relation=INVOKES/INPUT_OF/OUTPUT_OF）绑定到业务概念 |
| F3 | Agent 路由 | AgentService 新增 `algorithm` action type，与 tool_call/nl2sql/code_mode 并列 |
| F4 | 算法执行 | 复用 CodeExecutorService 的 Python 执行通道，传入 SQL 查询结果作为 input_data |
| F5 | 结果解读 | LLM 对算法输出结果进行自然语言解读，生成决策建议 |
| F6 | 前端管理 | 算法管理页面：注册、编辑、绑定概念、查看调用历史 |

### 2.2 后续需求（Phase 2/3，不在本次范围）

- 算法链式调用（多算法级联编排）
- 算法版本管理与回滚
- 算法执行结果缓存
- 算法性能监控与告警
- MCP 协议接入（支持外部算法服务）

## 三、数据模型设计

### 3.1 复用现有表结构

算法热加载最大程度复用现有数据模型，减少新增表。

#### ToolDefinition 表（复用）

现有 `tool_definition` 表，新增 `tool_type='ALGORITHM'` 类型，config 字段存储算法脚本路径：

| 字段 | 类型 | 说明 | 算法类型的值 |
|------|------|------|-------------|
| tool_type | VARCHAR(20) | 工具类型 | `ALGORITHM`（新增枚举值） |
| config | JSON | 配置 | `{"scriptPath": "/path/to/algorithm.py", "timeout": 30, "pythonVersion": "3.11"}` |
| input_schema | JSON | 输入参数 | `{"type": "object", "properties": {"line_id": {"type": "string"}, "quantity": {"type": "number"}}}` |
| output_schema | JSON | 输出参数 | `{"type": "object", "properties": {"feasible": {"type": "boolean"}, "utilization": {"type": "number"}}}` |

#### ToolConcept 表（复用，扩展 relation 枚举）

现有 `tool_concept` 表，relation 字段新增算法专用关系类型：

| 字段 | 类型 | 说明 | 新增值 |
|------|------|------|--------|
| relation | VARCHAR(16) | 关系类型 | `INVOKES`、`INPUT_OF`、`OUTPUT_OF`（新增） |

关系类型说明：

| 关系类型 | 方向 | 语义 | 示例 |
|---------|------|------|------|
| INVOKES | 概念 → 算法 | 此概念的业务问题可调用此算法 | 订单量 → INVOKES → 排产算法 |
| INPUT_OF | 概念 → 算法 | 此概念的数据是算法的输入参数 | 产能 → INPUT_OF → 排产算法 |
| OUTPUT_OF | 算法 → 概念 | 算法的输出对应此概念 | 排产算法 → OUTPUT_OF → 产能利用率 |

### 3.2 新增表：algorithm_execution_log

记录算法执行历史，用于监控和审计：

| 字段 | 类型 | 必填 | 说明 |

| execution_time_ms | INT | 否 | 执行耗时（毫秒） |
| success | BOOLEAN | 是 | 是否执行成功 |
| error_message | TEXT | 否 | 错误信息 |
| created_at | DATETIME | 是 | 创建时间 |

private void routeAlgorithm(Map<String, Object> data,
        List<Map<String, Object>> messages, Map<String, Object> parsed) {
    String algorithmName = (String) parsed.get("algorithm_name");
    @SuppressWarnings("unchecked")
    Map<String, Object> inputData = (Map<String, Object>) parsed.getOrDefault("input_data", Map.of());
    String toolCallId = "call_" + UUID.randomUUID().toString().replace("-", "").substring(0, 8);
    appendReasoning(data, (String) parsed.getOrDefault("reasoning", ""));
    data.put("next_action", "algorithm");
    data.put("pending_algorithm", Map.of(
        "algorithm_name", algorithmName,
        "input_data", inputData,
        "tool_call_id", toolCallId
    ));
    addAssistantToolCallMsg(messages, toolCallId, algorithmName, inputData);
}
```

**改动点 C**：新增 `buildAlgorithmExecutorNode()` 方法：

```java
private AsyncNodeAction<AgentState> buildAlgorithmExecutorNode() {
    return (state) -> {
        Map<String, Object> data = new LinkedHashMap<>(state.data());
        @SuppressWarnings("unchecked")
        Map<String, Object> algoCall = (Map<String, Object>) data.get("pending_algorithm");
        String algorithmName = (String) algoCall.get("algorithm_name");
        @SuppressWarnings("unchecked")
        Map<String, Object> inputData = (Map<String, Object>) algoCall.getOrDefault("input_data", Map.of());
        String toolCallId = (String) algoCall.get("tool_call_id");
        @SuppressWarnings("unchecked")
        List<Map<String, Object>> messages = (List<Map<String, Object>>) data.get("messages");

        // 1. 根据算法名称查找 ToolDefinition
        ToolDefinition algo = toolDefinitionRepository.findByName(algorithmName);
        if (algo == null || !"ALGORITHM".equals(algo.getToolType())) {
            messages.add(Map.of("role", "tool", "tool_call_id", toolCallId,
                "content", "算法 " + algorithmName + " 未找到或已禁用"));
            data.put("next_action", "continue");
            data.remove("pending_algorithm");
            return CompletableFuture.completedFuture(data);
        }

        // 2. 从 config 中获取脚本路径，执行算法脚本
        String scriptPath = algo.getConfig(); // JSON 中的 scriptPath
        Map<String, Object> result = codeExecutorService.executeScript(scriptPath, inputData);

        Boolean success = (Boolean) result.getOrDefault("success", false);
        if (success) {
            String stdout = (String) result.getOrDefault("stdout", "");
            messages.add(Map.of("role", "tool", "tool_call_id", toolCallId,
                "content", "算法 " + algorithmName + " 执行成功:\n" + stdout));
        } else {
            String stderr = (String) result.getOrDefault("stderr", "未知错误");
            messages.add(Map.of("role", "tool", "tool_call_id", toolCallId,
                "content", "算法 " + algorithmName + " 执行失败: " + stderr));
        }

        data.put("next_action", "continue");
        data.remove("pending_algorithm");
        return CompletableFuture.completedFuture(data);
    };
}
```

## 五、场景设计

### 5.1 场景总览

| 编号 | 场景 | 用户问题 | 核心算法 | 优先级 |
|:--:|------|------|------|:--:|
| S1 | 智能排产 | "下周三号线接不接得了 5000 件 A 产品订单？" | 排产可行性评估 | P0 |
| S2 | 需求预测 | "下个月 A 产品预计销量多少？需要备多少料？" | 时序预测 | P1 |
| S3 | 异常检测 | "最近一周哪些生产指标异常？" | 异常检测 | P0 |
| S4 | 库存优化 | "B 原料的安全库存应该设多少？" | 安全库存计算 | P1 |
| S5 | 质量根因 | "为什么 C 产品不良率从 2% 涨到 5%？" | 因果推断 | P0 |

### 5.2 场景 S1：智能排产（首发场景）

**本体概念**：订单量、产能、交期、产线、产品、工时

**算法定义**：

| 属性 | 值 |
|------|-----|
| 算法名 | 排产可行性评估 |
| 输入 | `line_id`（产线ID）、`daily_capacity`（日产能）、`already_scheduled`（已排产量）、`order_quantity`（订单量）、`deadline`（交期） |
| 输出 | `feasible`（是否可承接）、`suggested_start`（建议开始日期）、`completion_date`（预计完成日期）、`utilization`（产能利用率） |

**LLM 编排**：

| 步骤 | Action | 说明 |
|:--:|------|------|
| 1 | nl2sql | 查询三号线产能、已排产订单 |
| 2 | algorithm | 调用排产算法，传入 SQL 结果 |
| 3 | final_answer | 解读算法结果，输出决策建议 |

**概念绑定**：

```
订单量 ──INVOKES──→ 排产可行性评估
产能   ──INPUT_OF──→ 排产可行性评估
交期   ──INPUT_OF──→ 排产可行性评估
排产可行性评估 ──OUTPUT_OF──→ 产能利用率
```

| 输出 | `forecast_quantity`（预测销量）、`confidence_lower`（置信下限）、`confidence_upper`（置信上限） |

**LLM 编排**：

| 步骤 | Action | 说明 |
|:--:|------|------|
| 1 | nl2sql | 查询 A 产品近 12 个月销量 |

| 5 | final_answer | 输出预测销量 + 备料建议 |

### 5.4 场景 S3：异常检测

### 5.5 场景 S4：库存优化

**本体概念**：库存量、日消耗量、采购周期、供应商交期、安全库存

**算法定义**：

| 属性 | 值 |
|------|-----|
| 算法名 | 安全库存优化 |
| 输入 | `daily_consumption_mean`（日消耗均值）、`daily_consumption_std`（日消耗标准差）、`lead_time`（采购周期，天）、`service_level`（服务水平，如 0.95） |
| 输出 | `safety_stock`（建议安全库存）、`reorder_point`（再订货点）、`current_stock_status`（当前库存评估） |

**LLM 编排**：

| 步骤 | Action | 说明 |
|:--:|------|------|
| 1 | nl2sql | 查询 B 原料近 3 月消耗量、当前库存 |
| 2 | algorithm | 调用安全库存算法 |
| 3 | final_answer | 输出安全库存建议 + 库存评估 |

### 5.6 场景 S5：质量根因分析

**本体概念**：不良率、产品、批次、供应商、设备、工艺参数、质检结果

**算法定义**：

| 属性 | 值 |
|------|-----|
| 算法名 | 质量因果推断 |
| 输入 | `defect_rate_series`（不良率时序）、`factor_data`（各维度数据，JSON） |
| 输出 | `key_factors`（关键影响因素列表）、`contribution`（贡献度排序）、`confidence`（置信度） |

**LLM 编排**：

| 步骤 | Action | 说明 |
|:--:|------|------|
| 1 | nl2sql | 查询 C 产品不良率趋势（近 30 天） |
| 2 | DRILLS_INTO | 按批次、供应商、设备下钻 |
| 3 | nl2sql | 查询各维度数据 |
| 4 | algorithm | 调用因果推断算法 |
| 5 | final_answer | 输出根因报告（复用 root_cause JSON Schema） |

### 5.7 场景与 CODE_MODE 的关系

| 场景 | CODE_MODE（LLM 写代码） | ALGORITHM（企业算法） | 差异 |
|:--:|:--:|:--:|------|
| S1 排产 | 可写简单评估逻辑 | 企业排产算法（约束求解） | 算法更精确 |
| S2 预测 | 可写简单移动平均 | 企业时序模型（ARIMA/Prophet） | 算法更专业 |
| S3 异常 | 可写 3-sigma 检测 | 企业异常检测算法 | 算法更鲁棒 |
| S4 库存 | 可写简单公式 | 企业安全库存模型 | 算法更标准 |
| S5 根因 | 可写相关性分析 | 企业因果推断模型 | 算法更严谨 |

| E-07 | 用户问题无关算法场景 | LLM 不应调用算法，走 nl2sql+final_answer |
